# 约束协同平台设计

平台目标：每次协调会结束都能回答三个问题——

1. 哪项条件只是口头赞同
2. 哪项条件已由责任部门正式放行
3. 哪个堵点会改变整体工期

## 依赖图

`src/coordination/` 把以下对象组织成依赖图：

- 通道区段与方案版本：条件绑定到区段和方案版本
- 沿线城市与产业节点：挂在区段上，条件可关联到节点
- 条件：用地、用海、用能、标准规则、算力通信、风险韧性六类
- 里程碑：依赖其他里程碑，并要求若干条件先放行
- 审批事项：就绪与否由关联条件的状态推导

传播方向：条件变化 → 关联审批与门槛里程碑 → 下游里程碑。

## 部门承诺

每项承诺必须附带适用范围、期限与证据。证据分正式文件、会议纪要、视频发言、邮件往函四类，只有正式文件能支撑正式放行。承诺状态：

- 口头赞同：默认状态，任何过程性表态都停在这里
- 正式放行：经 `mark_formal_release` 校验范围、期限、正式文件证据后才能进入
- 已撤回：批准后撤回，立即触发重算

`condition_status` 在读取时再次校验：即使数据被误标为正式放行，只要缺少正式文件证据或期限已过，就绝不会被汇总成"已正式放行"，而是落入"待重核"。视频发言因此永远不可能被汇总数字误作正式放行。

## 事件与重算

以下事件都会沿依赖图重新计算受影响的审批和里程碑：

- 多方同时会签：`cosign` 按部门累积，覆盖全部应签部门即完成；审批就绪要求条件已放行且会签完成
- 批准后撤回：`withdraw_release` 把承诺置为已撤回，已批准的审批在 `recompute` 中转为待复核
- 跨年计划调整：`adjust_milestone_start` 移动里程碑后重算全部下游
- 方案换版：`change_plan_version` 把区段内绑定旧版的条件全部转为待重核，责任部门经 `reconfirm_condition` 重新确认后才恢复

## 标准裁决

相互冲突的标准通过 `file_conflict` 立案，关联条件转为"裁决中"，不再参与就绪判断。`rule_conflict` 作出裁决时必须给出结论和证据来源，裁决后条件解除阻塞。

## 敏感附件

附件标记敏感后只向 `allowed_regions` 中的获授权地区开放，其他地区 `accessible_by` 一律拒绝；非敏感附件对所有参与地区开放。

## 协调会三问报告

`meeting_report(as_of)` 输出：

- `verbal_only`：只有口头赞同、无有效正式放行的条件
- `formally_released`：正式放行生效（范围明确、期限未过、有正式文件证据）的条件
- `schedule_blockers`：未解除且卡在关键路径（总时差为零的里程碑所要求的条件）上的堵点

关键路径由里程碑依赖、计划开始时间与工期按 CPM 计算；不在关键路径上的堵点不会进入第三问。

## 演示

`src/coordination/demo.py` 构造了一条跨省通道样例（云州市、岚山市、临港算力园等均为虚构），覆盖六类条件、一次会签、一起标准冲突、两个堵点和一份敏感附件。运行测试即可看到三问报告与各类事件的重算行为：

```
python3 -m unittest discover -s tests -v
```
