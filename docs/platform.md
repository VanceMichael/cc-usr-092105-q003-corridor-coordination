# 约束协同平台设计

平台目标：每次协调会结束，项目办公室都能回答三个问题——
哪项条件只是口头赞同，哪项已由责任部门正式放行，哪个堵点会改变整体工期。

## 对象与依赖图

`src/model.py` 定义全部对象，`DependencyGraph` 记录“谁依赖谁”：

- 通道区段（Segment）是空间骨架，沿线城市、产业节点、算力通信配套、
  风险韧性要求都挂在区段上；
- 资源条件（用地/用海/用能）同时挂在区段与方案版本上；
- 部门承诺的适用范围指向资源条件；
- 审批（Approval）声明所需的承诺、条件与标准规则；
- 里程碑（Milestone）声明所需的审批。

事件发生后，从变化节点沿反向边扩散，只重算受影响的审批和里程碑。

## 承诺生命周期与证据等级

`src/commitments.py`：承诺只能沿“口头赞同 → 正式放行 → 已撤回”流转，
并附带适用范围（scope）、期限（not_before/not_after）与证据清单。

- 正式证据只有两类：正式函件、盖章文件；
- 视频发言、会议纪要可以归档，但 `release` 与 `countersign` 一律拒绝，
  因此视频发言永远不可能被汇总数字误作正式放行；
- 多方会签：每个会签方各自提交正式证据，全部到齐才转为正式放行；
- 批准后撤回必须说明理由并附正式证据，留痕备查；
- 承诺期限必须覆盖依赖它的里程碑计划日，否则视为期限不足。

## 事件与重算

`src/events.py` 定义四类事件，`ConstraintPlatform.apply` 应用后重算：

- 多方会签（CountersignEvent）：承诺可能转为正式放行，解锁下游审批；
- 批准后撤回（WithdrawalEvent）：依赖该承诺的审批由“有效”转为“已失效”，
  关联里程碑标记受阻；
- 跨年计划调整（PlanAdjustmentEvent）：里程碑日期更新后，承诺期限
  覆盖不了新计划日的，列入期限不足清单，相关审批失效；
- 方案换版（VersionChangeEvent）：旧版方案名下的资源条件全部转入待复核，
  复核确认（confirm_condition）到新版后才恢复效力。

审批三态：待确认、有效、已失效。曾有效而后提条件不满足的，记为已失效，
与从未满足的待确认区分开。每次重算产出 `ImpactReport`：状态变化的审批、
受阻里程碑、期限不足承诺与整体完工预测。

## 标准冲突裁决

`src/adjudication.py`：相互冲突的标准进入“已提出 → 举证中 → 已裁决”的
专门流程。裁决期间涉事规则暂缓使用，依赖它们的审批随之失效；裁决只能由
裁决委员会作出，结论须附正式证据并给出占优规则或统一条款。按占优规则
裁决后，依赖被替代规则的审批自动改按占优规则执行。

## 附件分级与地区授权

`src/access.py`：附件分公开、内部、敏感三级。查阅者密级须不低于附件密级；
敏感附件只向 authorized_regions 列明的获授权地区开放，
其他地区即使密级达标也会被拒绝。

## 协调会三问

`src/report.py` 的 `meeting_report` 输出：

1. 口头赞同：仍处于口头状态的承诺（包括只有视频发言支撑的）；
2. 正式放行：状态为正式放行、在有效期内且持有正式证据的承诺；
3. 工期堵点：未解除且影响关键里程碑的堵点，附影响的里程碑与延误天数；
   另附各里程碑预测日期与整体完工预测。

汇总数字只按承诺正式状态统计，与证据种类无关的口径在结构上被排除。
